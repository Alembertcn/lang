# MOJi 阅读计划接口

来源：MOJi 阅读 Android 3.4.9（`com.mojidict.read`）里 `ReadPlanRepository` 的 REST 调用。基址：

`https://api.mojidict.com/app/mojiread/api`

登录后请求带 `X-MOJI-TOKEN`（`POST /v1/account/unifiedLogin` 返回的 `sessionToken`）。登录响应含会话凭证，不落盘。

正文不在这些接口里。这里只有计划、章节和文章元数据。重新拉取：

```bash
python3 tools/fetch_moji_plans.py
```

脚本会覆盖本目录下的 `responses/` 和 `catalog.txt`。

## 响应字段

HTTP 200 时响应体就是下面的对象，没有再包一层 `code` / `result`。

### `readPlan.list.json`

| 字段 | 含义 |
|---|---|
| `readPlans[]` | 计划目录。`objectId`、`title`、`desc`、`artNum`、`level`、`cover`、`chapters[]` |
| `readPlans[].chapters[]` | `title`、`artIds[]`（文章 `objectId`） |
| `articles[]` | 这些 `artIds` 对应的文章元数据，键见下表 |
| `userReadPlans[]` | 各用户的阅读进度 |
| `users[]` | 进度里出现的用户 |
| `hasNext` | 是否还有下一页 |

本次 `hasNext` 为 `false`，19 个计划、205 篇文章都在这一页。

### `readPlan.mine.json`

当前账号已加入的计划，不是全站目录。本次只有 1 个计划。

| 字段 | 含义 |
|---|---|
| `userReadPlans[]` | `planId`、`dailyReading`、`doneArtIds`、`isCompleted`、`totalDuration` |
| `readPlans[]` | 对应计划 |
| `articles[]` | 这些计划里的文章元数据 |
| `readSuccess` | 已读完记录 |

### `readPlan.detail/{planId}.json`

| 字段 | 含义 |
|---|---|
| `readPlan` | 单个计划，含 `chapters` |
| `articles[]` | 该计划文章元数据 |
| `userReadPlan` | 当前用户在该计划上的进度；未加入则为空 |
| `readSuccess` | 已读完记录 |

### `articles[]` 常用字段

| 字段 | 含义 |
|---|---|
| `objectId` | 文章 ID，与 `chapters[].artIds` 对应 |
| `title` | 标题 |
| `excerpt` | 摘要 |
| `columnId` | 所属专栏 |
| `audioId` / `audioDuration` | 音频 |
| `charsNum` | 字数 |
| `levelTags` | 难度标签 |
| `isVIP` | 是否会员文 |
| `publishedAt` | 发布时间 |

`catalog.txt` 用计划标题、章节标题和 `articles[].title` 排成纯文本，方便直接看目录。

## 文章详情

计划接口没有正文。正文分三步，和客户端 `ArticleRepository` 一致：

1. `POST {parse}/functions/reading-article-detail`，参数 `objectId`、`isNlt=true`。Parse 基址是 `https://api.mojidict.com/app/mojiread/parse`。
2. `POST {parse}/functions/fetchTargetSrcUrl_v2`，参数 `targetType=210`（文章）、`targetId=objectId`。有注音时再加 `tag=notation`。返回一个 zip 地址。
3. 下载 zip，取出里面的 HTML，即文章主体。

句子列表是 `POST {parse}/functions/fav-listSens`，参数 `srcId=objectId`。这次 205 篇的 `result` 都是空数组，句子在 HTML 里。

每篇文章一个目录，目录名是文章 `objectId`：

| 内容 | 文件 |
|---|---|
| `reading-article-detail` 响应 | [articles/{objectId}/detail.json](articles/) |
| zip 解出的正文 | [articles/{objectId}/body.html](articles/) |
| `fav-listSens` 响应 | [articles/{objectId}/sentences.json](articles/) |

重新拉取：`python3 tools/fetch_moji_articles.py`。本次 205 篇全部成功。

## 文章录音

`detail.json` 的 `result.audioId` 就是文件名。线上地址和对象键：

`https://oss.mojidict.com/article/audio/{audioId}`

本地按同样的路径放在 [oss/article/audio/](oss/article/audio/)，静态服务把 `reference/moji-api/oss` 当作根目录即可 mock 这个 host：

```bash
python3 -m http.server 8765 --directory reference/moji-api/oss
# http://127.0.0.1:8765/article/audio/{audioId}
```

[audio-index.json](audio-index.json) 把文章 `objectId`、标题、时长映射到 `file`（相对 `reference/moji-api/`）。没有 `audioId` 的文章列在 `missingAudio`。重新拉取：`python3 tools/fetch_moji_audio.py`。

这些 mp3 只给本地 mock 用，不放进 `composeResources`，避免打进安装包。应用自己合成的连续音频仍在 `composeResources/files/article_audio`。
